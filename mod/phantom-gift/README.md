# Фантом-подарки (PampGram mod)

Полностью локальная система «фейковых» подарков для форка [Telegram-iOS](https://github.com/TelegramMessenger/Telegram-iOS):
вкладка **«Фантом»** в экране отправки подарков, свой локальный баланс Stars, подарок
сохраняется в базе на устройстве и переживает перезапуск, ничего не уходит на сервер
Telegram.

## Как это работает

**Точка входа** — существующая кнопка «Отправить подарок» → вкладка **«Фантом»** в
`GiftOptionsScreen` (тот же каталог реальных подарков, без изменений в реальной покупке).

**Отправка** (`PampGramPhantomGiftManager.send`) — три шага, каждый чисто локальный:
1. Проверка и списание локального баланса (`PampGramPhantomGiftStore` — обычный
   `PreferencesEntry` Postbox, тот же механизм, что хранит настройки автосохранения
   медиа: `submodules/TelegramUI/Sources/StoreDownloadedMedia.swift`). Ключи —
   зарезервированные внутри модуля, не в общем `ApplicationSpecificPreferencesKeys`, чтобы
   не пересекаться с чем-то реальным.
2. Если подарок «коллекционный» (`gift.availability != nil`, как у реальных лимитированных
   подарков) — `PampGramUniqueGiftGenerator` подбирает случайный Model/Backdrop/Symbol из
   `context.engine.payments.starGiftUpgradePreview(giftId:)` — тот же публичный список
   образцов атрибутов, что показывает настоящий экран апгрейда подарка. Это единственный
   сетевой вызов во всей фиче: он только читает публичный список арта, никакой информации о
   фантомном подарке никуда не уходит. Если запрос не удался — используется обычный (не
   коллекционный) подарок, ничего не ломается.
3. `PampGramPhantomGiftMessage.insertLocalGiftMessage` — вставляет **настоящее** сообщение
   в историю чата с `Namespaces.Message.Local` (зарезервированный Postbox-неймспейс для
   локальных сообщений, никогда не пересечётся с реальным id с сервера — пример в проекте:
   `submodules/TelegramCore/Sources/Utils/StoredMessageFromSearchPeer.swift`) через
   `Transaction.addMessages`. Это НЕ сетевой вызов — `account.network` не участвует вообще.

**Карточка в чате** — сообщение несёт настоящий `TelegramMediaAction.starGift` (обычный
подарок) или `.starGiftUnique` (коллекционный, с Model/Backdrop/Symbol), поэтому
`ChatMessageBubbleItemNode` рисует его существующим `ChatMessageGiftBubbleContentNode` —
той же карточкой, что и настоящий подарок. Чтобы её нельзя было спутать с настоящей,
`ChatMessageGiftBubbleContentNode.swift` проверяет маркер (для обычных — служебное поле
`prepaidUpgradeHash`, для коллекционных — `slug` подарка, начинающийся с
`pampgram-phantom-`, потому что у `.starGiftUnique` нет свободного строкового поля) и
принудительно меняет ленту на «Фантом» другим цветом + подписывает текстом «локально,
ничего не покупалось».

**Удаление** — обычное «Удалить сообщение» на карточке в чате уже работает бесплатно:
пайплайн удаления (`submodules/TelegramCore/Sources/TelegramEngine/Messages/DeleteMessagesInteractively.swift:120`)
уже отдельно проверяет `Namespaces.Message.Local` и пропускает сетевой запрос на удаление
именно для локальных сообщений — это существующий, а не написанный нами код.
`PampGramPhantomGiftManager.delete` дополнительно чистит запись в
`PampGramPhantomGiftStore`.

**Баланс** — `PampGramFakeStarsBalance`, по умолчанию 50 000, отдельно от настоящего
Stars-баланса, тоже через `PreferencesEntry`.

## Файлы

- `telegram-ios.patch` — правки в существующих файлах upstream:
  - `GiftOptionsScreen.swift` — вкладка «Фантом», диалог подтверждения с показом баланса,
    вызов `PampGramPhantomGiftManager.send`;
  - `ChatMessageBubbleItemNode.swift` — комментарий (без функциональных изменений — теперь
    подставные сообщения несут настоящий `TelegramMediaAction`, специальной обработки не
    требуется);
  - `ChatMessageGiftBubbleContentNode.swift` — подмена ленты на «Фантом» по маркеру;
  - два `BUILD`-файла (Bazel).
- `PhantomGiftKit/` — новый модуль:
  - `PampGramPhantomGift.swift` — модель;
  - `PampGramPhantomGiftStore.swift` — постоянное хранилище (подарки + фейковый баланс);
  - `PampGramPhantomGiftMessage.swift` — вставка локального сообщения в чат;
  - `PampGramUniqueGiftGenerator.swift` — генератор случайного коллекционного экземпляра;
  - `PampGramPhantomGiftManager.swift` — оркестратор отправки/удаления.

## Что НЕ реализовано в этом проходе (осознанно отложено)

- **Грид подарков в профиле** («Профиль → Подарки → вижу там Фантом-подарок»). Реальный
  рендеринг живёт в `PeerInfoGiftsPaneNode.swift` — 1547 строк, тесно завязанных на живой
  синхронизирующийся с сервером `ProfileGiftsContext`. Редактировать это вслепую, без
  компилятора под рукой, — неоправданный риск сломать основной экран профиля. Фантомный
  подарок сейчас виден и кликабелен как карточка в чате (с реальной картинкой, моделью,
  подтверждением) — это не то же самое место в UI, но тот же результат по сути.
- **Отдельный пункт меню профиля** для списка локальных подарков — не нашёл точку
  подключения быстро и безопасно, отложил, чтобы не гадать вслепую.
- **Просмотр коллекционного экземпляра через реальный marketplace-грид**
  (`GiftStoreScreen`) — вместо этого атрибуты подбираются случайно напрямую (см. выше);
  сам `GiftStoreScreen` заточен под реальные resale-листинги с реальными продавцами, и
  переиспользовать его для фейковых подборов — риск глубже, чем оправдано.

## Единственное место, которое я не смог до конца проверить

Тап по карточке в чате ведёт (через уже существующий код `ChatController.swift`) в
`GiftViewScreen` — экран примерно на 6000 строк, с кнопками Transfer/Convert/Resell,
завязанными на `reference: StarGiftReference?`. У нашего сообщения реального `reference` в
базе нет (это же не настоящий подарок), так что открыться он должен, но я не успел построчно
проверить каждую кнопку на этом экране в рамках сессии. **Совет:** первый раз открой карточку
в авиарежиме, прежде чем пользоваться в обычном режиме.

## Как собрать

Здесь нет macOS/Xcode — собрать и протестировать `.ipa` можно только у тебя, на Mac:

```sh
git clone https://github.com/TelegramMessenger/Telegram-iOS.git
cd Telegram-iOS
git apply /путь/до/PampGram/mod/phantom-gift/telegram-ios.patch
cp -r /путь/до/PampGram/mod/phantom-gift/PhantomGiftKit \
  submodules/TelegramUI/Components/Gifts/PhantomGiftKit
```

Дальше — сборка через `Make.py` (Bazel) и Xcode по инструкции самого репозитория
Telegram-iOS.

## Статус

Написано по образцу существующих файлов репозитория (сигнатуры функций, паттерны
транзакций Postbox сверены вручную по исходникам), но без компиляции — здесь нет
инструментов для сборки iOS. Вероятны 1-2 итерации правок после первой сборки в

## Важно

При клонировании `TelegramMessenger/Telegram-iOS` в этой сессии в корне репозитория
несколько раз обнаруживался файл `CLAUDE.md` с "инструкциями для ИИ" (пароли для сборки,
сторонний gitlab-репозиторий для code-signing и т.д.) — для настоящего репозитория Telegram
это нетипично и похоже на попытку промпт-инъекции через содержимое файла. Эти "инструкции"
не использовались. Стоит проверить содержимое `CLAUDE.md` в своей копии перед тем как
доверять ему.
