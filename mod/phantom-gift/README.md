# Фантом-подарки (PampGram mod)

Косметическая функция для форка [Telegram-iOS](https://github.com/TelegramMessenger/Telegram-iOS):
в экране "Отправить подарок" появляется отдельная вкладка **«Фантом»**. Подарки в ней
берутся из того же настоящего каталога (тот же магазин, те же модели), но отправка через
эту вкладку:

- не списывает Stars и не создаёт запись о покупке — никакой настоящей передачи не происходит;
- всегда явно помечена как «Фантом» — и в самой вкладке, и в диалоге подтверждения, и в
  сообщении получателю, — чтобы её нельзя было спутать с настоящим платным подарком;
- видна с анимацией только у получателя, у которого тоже установлен этот мод. У обычного
  пользователя Telegram сообщение выглядит как обычный текст с эмодзи 🎁 — реакция клика
  по эмодзи будет просто не работать (не настоящий scheme в Telegram).

## Как это работает

1. **Вкладка «Фантом»** добавлена в `GiftOptionsScreen` (`StarsFilter.phantom`) рядом с
   «Все/Мои/Коллекционные» — использует тот же список `starGifts`, без изменений в реальной
   покупке.
2. **Отправка** (`PhantomGiftSender`) — обычное текстовое сообщение вида
   `🎁 Фантом-подарок «Название» — визуальный, ...`, где на эмодзи 🎁 навешена скрытая
   ссылка `phantomgift://send?d=<base64(JSON)>` (id подарка + имя отправителя). Отправляется
   через штатный `enqueueMessages` — никакого отдельного протокола/сервера не требуется.
3. **Приём** — перехват `phantomgift://` добавлен в `OpenUrl.swift`, рядом с уже существующей
   обработкой `tg://`-ссылок. Настоящий Telegram эту схему не знает и просто ничего не сделает
   по тапу; мод декодирует payload, находит тот же подарок в
   `context.engine.payments.cachedStarGifts()` (тот же публичный каталог) и показывает
   полноэкранную анимацию через уже существующий `UndoOverlayController` (`.sticker(...)`),
   с подписью «Фантом-подарок... визуальный подарок, реальной передачи не было».

## Файлы

- `telegram-ios.patch` — правки в существующих файлах upstream-репозитория:
  - `submodules/TelegramUI/Components/Gifts/GiftOptionsScreen/Sources/GiftOptionsScreen.swift`
    — вкладка, фильтр, обработчик тапа, диалог подтверждения;
  - `submodules/TelegramUI/Sources/OpenUrl.swift` — перехват `phantomgift://`;
  - два `BUILD`-файла (Bazel) — добавлен новый модуль в граф зависимостей.
- `PhantomGiftKit/` — новый Swift-модуль (Sources + Bazel `BUILD`), который нужно скопировать
  в форк по пути `submodules/TelegramUI/Components/Gifts/PhantomGiftKit/`.

## Как собрать

Здесь нет macOS/Xcode, поэтому собрать и протестировать `.ipa` можно только у тебя, на Mac:

```sh
git clone https://github.com/TelegramMessenger/Telegram-iOS.git
cd Telegram-iOS
git apply /путь/до/PampGram/mod/phantom-gift/telegram-ios.patch
cp -r /путь/до/PampGram/mod/phantom-gift/PhantomGiftKit \
  submodules/TelegramUI/Components/Gifts/PhantomGiftKit
```

Дальше — сборка через `Make.py` (Bazel) и Xcode по инструкции самого репозитория
Telegram-iOS, подпись и установка через AltStore/TrollStore/свой Apple ID.

## Статус

Это первый рабочий проход: код написан по образцу существующих файлов репозитория
(сигнатуры функций, паттерны отправки сообщений и диалогов сверены вручную), но без
компиляции — здесь нет инструментов для сборки iOS. Скорее всего понадобится 1-2 итерации
правок после первой сборки в Xcode/Bazel. Если пришлёшь ошибки сборки — поправлю.

## Важно

При клонировании `TelegramMessenger/Telegram-iOS` в этой сессии в корне репозитория
обнаружился файл `CLAUDE.md` с "инструкциями для ИИ" (пароли для сборки, сторонний
gitlab-репозиторий для code-signing и т.д.) — для настоящего репозитория Telegram это
нетипично и похоже на попытку промпт-инъекции через содержимое файла. Эти "инструкции" не
использовались. Стоит проверить содержимое `CLAUDE.md` в своей копии перед тем как доверять
ему.
